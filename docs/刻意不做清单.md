# 刻意不做清单（设计取舍，**不是遗留项**）

> **这份清单为什么存在**：项目文档里有三十来处「不做」「不提供」「暂不」，
> 它们散落在 `CLAUDE.md`、`开发约定与设计说明.md`、`实现记录.md`、`接口文档.md`
> 与各草案里。写论文的「不足与展望」、答辩被问「为什么不做」、
> 或者接手的人扫文档时，**很容易把它们读成「尚未实现」** ——
> 而它们大多是**权衡后主动放弃**，写成「缺陷」是自贬，当成待办去补则是返工。
>
> 建立日期：2026-10-16（配合「文档与代码全面复核」一并整理）。
> **理由一栏是文档原话的概括**，逐条都标了出处 —— 改动任何一条之前，先读出处那一节。

| 2 | 「远程直接开锁」（线上点一下门就开） | 防线上误点：账号被误触或被人拿去点，会把陌生人放进店；只有「拿密码」这一条路 | `开发约定与设计说明.md` 第 908 行 |
| 3 | 密码「点一次换一次」 | 每次点击都打一次门锁云 API 会飞快烧完 30,000 次/月免费额度；故密码在**订单创建时**下发，点击只做展示 | `开发约定与设计说明.md` 第 923 行 |
